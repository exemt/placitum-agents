# Placitum agents

[English](README.md) · Русский

Агенты наблюдения Placitum: маленькие процессы, которые рассказывают установке, как себя чувствует
инфраструктура рядом с ними. Каждый — свой Go-модуль и свой образ.

| Каталог | Образ | Что делает |
| --- | --- | --- |
| [`redis/`](redis) | `placitum/agents-redis` | здоровье, память и ключи одного экземпляра Redis; кадр присутствия `WAF_STATUS.store.redis.<id>` |
| [`s3/`](s3) | `placitum/agents-s3` | бакеты архива: доступность, размер, темп запросов; кадр `WAF_STATUS.store.s3.<id>`. Бакеты заводит сам |
| [`haproxy/`](haproxy) | `placitum/agents-haproxy` | haproxy с агентом в одном контейнере; конфигурацию ведёт контроллер |

Первые два только наблюдают: своего состояния не держат, на трафик не влияют, и потеря агента на
хранилище и установке не сказывается. Третий — балансировщик с управляемой конфигурацией. Его агент
живёт на самом узле, потому что `haproxy -c` обязан проверять конфиг тем же бинарём, который
держит трафик. У всех троих один контракт — кадр присутствия на `WAF_STATUS`, — и правятся они
обычно вместе, поэтому живут в одном репозитории; контекст сборки умеет каталог.

## Сборка

Каждый образ собирается из своего каталога:

```sh
docker build -t placitum/agents-redis redis
docker build -t placitum/agents-s3 s3
docker build -t placitum/agents-haproxy haproxy
```

Из git — каталогом в контексте сборки:

```sh
docker buildx build -t placitum/agents-redis "https://github.com/exemt/placitum-agents.git#<ref>:redis"
```

Настройки каждого агента — в [INSTALL.ru.md](INSTALL.ru.md).
